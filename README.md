# The Agency 6 — Task Manager

Статичний міні-сайт для менеджменту проєкту **The Agency 6** (Unity HDRP, ізометричний кіберпанк-детектив).
Без збірки та залежностей: відкрийте `index.html` у браузері.

## Розділи

| Розділ | Що показує |
| --- | --- |
| **Огляд** | % готовності, відкриті P0, критичні прогалини, прогрес за фазами та епіками, «можна брати зараз» (задачі з закритими залежностями) |
| **Дошка** | Kanban: Backlog → До виконання → В роботі → Рев'ю → Готово; перетягування карток змінює статус |
| **Список** | Таблиці задач за фазами A–E з епіком, типом, пріоритетом, оцінкою, залежностями |
| **Роадмап** | Ганта на 13 тижнів + склад кожної фази |
| **Прогалини** | 15 розбіжностей між GDD і кодом гілки `Development`, кожна з пов'язаними задачами |
| **Візуал** | HTML/CSS-макети: діалогове вікно, верстак модулів, інвентар і руки, вибір психотипу, стани «невидимої механіки» |

**GDD (`gdd.html`)** — окрема сторінка з геймдизайн-документом: зміст із підсвіткою поточного розділу, пошук по тексту, прогрес читання, друк у PDF і задачі дошки під кожним розділом. Текст лежить у блоці `<script type="text/markdown" id="gddSource">` усередині `gdd.html`; щоб оновити сторінку, вставте туди свіжий експорт документа в Markdown.

Клік на задачу відкриває картку: опис, критерії готовності (чекбокси), залежності, що вона блокує, файли в коді, розділ GDD, статус, виконавець, нотатки.

**Скасування:** у картці будь-якої задачі є «✕ Скасувати задачу». Вона переходить у колонку «Скасовано», не враховується у відсотку готовності й не блокує залежні задачі. «↺ Відновити задачу» повертає її в Backlog. Видалити можна лише задачі, створені в інтерфейсі.

**Розвиток (`ideas.html`)** — ключові питання з варіантами рішень і рекомендацією, важливі принципи, нові фічі на матриці «користь / зусилля», ідеї DLC, кастомізація, розширення проєкту, шлях до релізу.

**Модулі (`modules.html`)** — каталог 55 модулів гри (Core / Features): призначення, неймспейси, інтерфейси, інсталери, конфіги, залежності, пов'язані задачі; автоматичні попередження (Core залежить від Features, немає опису, немає інтерфейсів, «хаб»); правила структури і шаблон README для модуля. Оновити дані після змін у грі:

```bash
python tools/gen_modules.py "D:/Git/MyProjects/Agency-6-HDRP"
```

**3D-моделі (`models.html`)** — покриття предметів із GDD моделями, каталог паків, арт-гайд, ризики. Оновлення: `python tools/gen_assets.py "D:/Git/MyProjects/Agency-6-HDRP"`.

**Звук (`sound.html`)** — покриття потреб гри звуками, звук станів персонажа, каталог аудіо, саунд-гайд, ризики. Оновлення: `python tools/gen_audio.py "D:/Git/MyProjects/Agency-6-HDRP"`.

**Живий прогрес на всіх сторінках** — під шапкою кожної сторінки смуга прогресу гри; чипи задач (`data-task`) і блоки прогресу (`data-progress="epic:AUD"`, `phase:S`, `tasks:AG-001,AG-002`) оновлюються наживо, щойно хтось змінює дошку.

## Спільна дошка (Supabase + вхід за email)

Статуси, нотатки, виконавці й нові задачі зберігаються в Supabase. Читати може будь-хто, редагувати — люди зі списку редакторів. Вхід: ввести email → натиснути посилання в листі (без пароля, працює й на телефоні). Зміни інших з'являються миттєво (Realtime), автора й журнал ставить сама база. Email у публічних даних не зберігається — лише ім'я.

### Налаштування (один раз, власник, ~5 хв)

1. **Проєкт.** [supabase.com/dashboard](https://supabase.com/dashboard) → New project (безкоштовний план).
2. **База.** SQL Editor → New query → вставити [`supabase/schema.sql`](supabase/schema.sql) → у кінці файлу замінити `owner@example.com` на email редакторів → **Run**.
3. **Адреса сайту.** Authentication → URL Configuration:
   - Site URL: `https://kosheew.github.io/The-Agency-6-Task-Manager/`
   - Redirect URLs → Add: `https://kosheew.github.io/The-Agency-6-Task-Manager/**`
4. **Ключі.** Project Settings → API → скопіювати **Project URL** і **anon public** key у [`data/config.js`](data/config.js) → закомітити й запушити. anon key публічний за задумом; **service_role key сюди не вставляйте**.

Вхід за email у Supabase увімкнений за замовчуванням — нічого додатково налаштовувати не треба. Вбудована пошта Supabase надсилає кілька листів на годину; для невеликої команди цього досить, бо вхід запам'ятовується.

### Редактори

Додати людину — Supabase → Table Editor → `board_members` → Insert row → `email`. Людина без доступу після входу бачить статус «гість» і свій email, щоб передати його власнику. Ім'я для журналу кожен задає сам у профілі.

Поки `data/config.js` порожній, дошка працює локально (зміни видно лише у вашому браузері).

## Де живуть дані

- **`data/tasks.js`** — базові задачі, фази, епіки та прогалини. Редагуйте цей файл і комітьте, щоб зміни бачила вся команда.
- **Браузер (localStorage)** — статуси, нотатки, галочки критеріїв і нові задачі, створені кнопкою «+ Задача». Вони локальні для вашого браузера.
- **Експорт / Імпорт** — вивантажує всі задачі та локальні зміни в JSON і завантажує назад (наприклад, щоб передати колезі).
- **Скинути** — стирає локальні зміни й повертає стан із `data/tasks.js`.

## Структура

```
index.html, gdd.html, ideas.html, modules.html, models.html, sound.html   сторінки
assets/styles.css      тема в стилі HUD гри, адаптив до 375 px
assets/app.js          дошка: рендер, фільтри, drag&drop, картка задачі, вхід
assets/sync.js         спільна дошка через Supabase (вхід GitHub, Realtime)
assets/board-live.js   живий прогрес дошки на всіх сторінках
data/tasks.js          задачі, фази, епіки, прогалини
data/config.js         адреса і публічний ключ Supabase
data/*.js              згенеровані каталоги (модулі, 3D, звук)
supabase/schema.sql    таблиці, права доступу, тригери, Realtime
tools/gen_*.py         генератори каталогів з репозиторію гри
```

## Нумерація

- `KAN-xx` — задачі, що вже злиті в репозиторій гри (з історії git).
- `AG-xxx` — план робіт за GDD. Нові задачі з інтерфейсу продовжують цю нумерацію.
