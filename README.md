# The Agency 6 — Task Manager

Статичний міні-сайт для менеджменту проєкту **The Agency 6** (Unity HDRP, ізометричний кіберпанк-детектив).
Без збірки та залежностей: відкрийте `index.html` у браузері.

## Розділи

| Розділ | Що показує |
| --- | --- |
| **Огляд** | % готовності, відкриті P0, критичні прогалини, прогрес за фазами та епіками, «можна брати зараз» (задачі з закритими залежностями) |
| **Дошка** | Kanban: Backlog → До виконання → В роботі → Рев'ю → Готово; перетягування карток змінює статус |
| **Список** | Таблиці задач за фазами A–E з епіком, типом, пріоритетом, оцінкою, залежностями |
| **Роадмап** | Ганта на 13 тижнів + склад кожної фази |
| **Прогалини** | 15 розбіжностей між GDD і кодом гілки `Development`, кожна з пов'язаними задачами |
| **Візуал** | HTML/CSS-макети: діалогове вікно, верстак модулів, інвентар і руки, вибір психотипу, стани «невидимої механіки» |

**GDD (`gdd.html`)** — окрема сторінка з геймдизайн-документом: зміст із підсвіткою поточного розділу, пошук по тексту, прогрес читання, друк у PDF і задачі дошки під кожним розділом. Текст лежить у блоці `<script type="text/markdown" id="gddSource">` усередині `gdd.html`; щоб оновити сторінку, вставте туди свіжий експорт документа в Markdown.

Клік на задачу відкриває картку: опис, критерії готовності (чекбокси), залежності, що вона блокує, файли в коді, розділ GDD, статус, виконавець, нотатки.

**Скасування:** у картці будь-якої задачі є «✕ Скасувати задачу». Вона переходить у колонку «Скасовано», не враховується у відсотку готовності й не блокує залежні задачі. «↺ Відновити задачу» повертає її в Backlog. Видалити можна лише задачі, створені в інтерфейсі.

**Розвиток (`ideas.html`)** — ключові питання з варіантами рішень і рекомендацією, важливі принципи, нові фічі на матриці «користь / зусилля», ідеї DLC, кастомізація, розширення проєкту, шлях до релізу.

**Модулі (`modules.html`)** — каталог 55 модулів гри (Core / Features): призначення, неймспейси, інтерфейси, інсталери, конфіги, залежності, пов'язані задачі; автоматичні попередження (Core залежить від Features, немає опису, немає інтерфейсів, «хаб»); правила структури і шаблон README для модуля. Оновити дані після змін у грі:

```bash
python tools/gen_modules.py "D:/Git/MyProjects/Agency-6-HDRP"
```

## Спільна дошка (синхронізація)

Статуси, нотатки, виконавці й нові задачі можна зберігати спільно для всієї команди:

1. Кнопка **«Увійти через GitHub»** у шапці → вкладка «Я власник» (fine-grained токен, лише цей репозиторій, **Contents: Read and write**) або «Я учасник команди» (classic токен з `public_repo`, після запрошення в collaborators) → вставити токен → **Верифікувати**. Сайт сам отримує з GitHub логін, ім'я й аватар — ім'я вручну не вводиться.
2. Після підключення кожна зміна стає комітом у `state/board.json` (повідомлення виду `board: AG-006 → В роботі — Андрій`).
3. Інші бачать зміни автоматично: сайт перевіряє стан кожні 30–90 с, показує сповіщення і стрічку «Остання активність команди» на Огляді.
4. Без токена дошка показує спільний стан у режимі перегляду; власні зміни тоді лише локальні.

Токен зберігається тільки в localStorage браузера і надсилається лише на `api.github.com`. Учасників команди треба додати в репозиторій як collaborators. Коміти в `state/` не перезбирають сайт.

## Де живуть дані

- **`data/tasks.js`** — базові задачі, фази, епіки та прогалини. Редагуйте цей файл і комітьте, щоб зміни бачила вся команда.
- **Браузер (localStorage)** — статуси, нотатки, галочки критеріїв і нові задачі, створені кнопкою «+ Задача». Вони локальні для вашого браузера.
- **Експорт / Імпорт** — вивантажує всі задачі та локальні зміни в JSON і завантажує назад (наприклад, щоб передати колезі).
- **Скинути** — стирає локальні зміни й повертає стан із `data/tasks.js`.

## Структура

```
index.html        розмітка, вкладки, візуальні макети
assets/styles.css тема (темний ретро-кіберпанк), адаптив до 375 px
assets/app.js     логіка: рендер, фільтри, drag&drop, картка задачі, експорт
data/tasks.js     дані проєкту
```

## Нумерація

- `KAN-xx` — задачі, що вже злиті в репозиторій гри (з історії git).
- `AG-xxx` — план робіт за GDD. Нові задачі з інтерфейсу продовжують цю нумерацію.
