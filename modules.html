Правила структури (з README)

  • Core — портативні модулі без залежностей від домену гри (Save, Pool, Input, FSM). Їх можна перенести в інший проєкт без змін.
  • Global — інфраструктура цієї гри, спільна для всього проєкту.
  • Features — вертикальні зрізи функціональності (ItemSystem, EntitySystem, WeaponSystem…).
  • Тека *System групує підмодулі; у коді суфікс System не вживається. Корінь неймспейсу — *Module (PlayerSystem → PlayerModule).
  • Підмодуль оголошує ParentModule.SubName (PlayerSystem/Stats → PlayerModule.Stats).
  • Компонент, потрібний одному підмодулю, лежить усередині нього, а не в спільній теці.
  • Сервіси й реєстри — instance-класи за інтерфейсом через Zenject, не static.
  • Model–Component: дані окремо від MonoBehaviour.

Що перевіряє ця сторінка

  • Core → Features модуль Core використовує неймспейс модуля гри — порушення правила портативності.
  • Без опису модуль не має короткого опису в генераторі.
  • Без інтерфейсів у модулі є код, але немає публічних інтерфейсів для DI.
  • Хаб модулем користуються 8+ інших — зміни в ньому ризиковані.
